# Attention Web 设计系统

状态：当前 Web 实现的视觉契约。实现入口是 [`apps/web/src/app/globals.css`](../apps/web/src/app/globals.css)。

## 1. 产品气质

Attention 是“人筛选，AI 整理”的信息层。界面要像一个安静、可靠的工具，而不是内容营销页：让内容和下一步行动占据注意力，视觉装饰只用于表达状态和来源。

核心原则：

- 基础界面使用黑、白、灰；不要引入暖米色、纸张色或独立页面底色。
- 蓝色表示 AI、链接和主要行动。
- 珊瑚色表示人的筛选、推荐或需要注意的入口。
- 颜色表达语义，不作为装饰。一个区域最多保留一个主要强调色。
- 页面优先使用实色表面、细边框和克制阴影；不要添加背景纹理、漂浮光晕或无意义渐变。
- 每个页面只保留一个明确的主要任务和一个主要行动。

## 2. 颜色 Token

所有新页面优先使用 CSS Token，不直接写新的十六进制颜色。

| Token | 值 | 用途 |
| --- | --- | --- |
| `--canvas` | `#ffffff` | 页面和文档背景 |
| `--surface` | `#fefefe` | 卡片、表单、弹窗表面 |
| `--surface-muted` | `#f4f4f5` | 次级信息块、已发送验证码 |
| `--surface-input` | `#fbfdfc` | 输入框需要轻微内收时的表面 |
| `--ink` | `#1d1d1f` | 标题、正文、主要控件 |
| `--muted` | `#707075` | 说明、元信息、次级操作 |
| `--line` | `#e6e6e2` | 默认分隔线和边框 |
| `--line-strong` | `#d8d8d4` | 输入框、需要更强边界的控件 |
| `--ai-signal` | `#0066ff` | 主要按钮、链接、焦点、AI 标识 |
| `--ai-signal-hover` | `#005be6` | 主要按钮悬停态 |
| `--ai-soft` | `#eaf2ff` | AI 状态的浅色背景 |
| `--ai-summary-soft` | `#f5f7ff` | AI 摘要的低对比背景 |
| `--human-signal` | `#ff6b5f` | 人的筛选、推荐、入口提示 |
| `--human-soft` | `#fff0ee` | 人工边界或提醒的浅色背景 |
| `--human-ink` | `#63221c` | 珊瑚语义区域中的正文色 |
| `--success` | `#147d64` | 成功、可用、公开 |
| `--success-soft` | `#edf8f4` | 成功状态背景 |
| `--danger` | `#c43228` | 错误、阻止、不可用 |
| `--danger-soft` | `#fff1f0` | 错误状态背景 |
| `--warning` | `#8a6500` | 等待、风险、需要确认 |
| `--warning-soft` | `#fff8df` | 警告状态背景 |

### 颜色使用规则

- 正文必须使用 `--ink` 或 `--muted`，不要用纯黑 `#000`。
- 主按钮统一使用 `--ai-signal`；悬停态使用比它更深的蓝色。
- `--human-signal` 不用于主按钮，不用于大面积背景。
- 状态颜色只表达状态，不用来区分页面模块。
- `rgba(255, 255, 255, …)` 只用于玻璃导航或叠加层；不能代替 `--surface`。
- 任何新增颜色必须先说明语义，再决定是否升级为 Token。

## 3. 字体与文字

```css
--font-display: "SF Pro Display", "PingFang SC", -apple-system,
  BlinkMacSystemFont, "Segoe UI", sans-serif;
--font-body: "SF Pro Text", "PingFang SC", -apple-system,
  BlinkMacSystemFont, "Segoe UI", sans-serif;
--font-data: "SFMono-Regular", "SF Mono", ui-monospace, Consolas, monospace;
```

- 正文默认 `16px / 1.625`，使用 `--font-body`。
- 页面标题使用 `--font-display`，紧凑字距和中高字重；标题要短，不用宣传口号堆叠层级。
- 数据、短标签、技术状态使用 `--font-data`，只在确实表达数据或系统状态时使用。
- 正文采用句首大写/自然中文，不整段大写。短标签可以使用小型大写，但不要把普通说明文字变成标签。
- 文案使用用户能理解的动作：`登录`、`保存`、`确认绑定`、`查看我的收藏`。避免 `Submit`、`执行流程` 等系统术语。
- 说明文字回答“接下来会发生什么”，错误文字回答“发生了什么以及怎么恢复”。

### 推荐层级

| 层级 | 默认处理 |
| --- | --- |
| 页面标题 | `PageIntro` 的 `h1`，约 `2–3rem`，紧凑字距 |
| 卡片标题 | `h2`，约 `1.2–1.45rem`，字重高于正文 |
| 正文 | `16px / 1.625`，`--ink` |
| 说明 | `14px` 左右，`--muted`，行高约 `1.55–1.65` |
| 元信息 | `11–13px`，`--muted`；只有必要时使用等宽字体 |

## 4. 空间、容器与圆角

```css
--page-gutter: 16px; /* 桌面宽屏覆盖为 32px */
--content-wide: 1320px;
--content-stream: 720px;
--content-form: 680px;
--radius-control: 12px;
--radius-card: 16px;
```

页面层级使用固定语义，不在组件中临时发明 `z-index`：header `20`、sticky 内容 `30`、modal 遮罩 `90`、modal surface `100`、toast `110`、skip link `120`。

### 使用层级

- 页面水平边距：移动端 `16px`；桌面宽屏 `32px`。
- 页面内容使用 `page-shell`，不要为单个页面重新发明最大宽度。
- 表单页面使用 `page-shell--form`；公开流使用 `page-shell--stream`；账户列表使用 `page-shell--mine` 或对应的账户容器。
- 输入框、选择器、信息块使用 `--radius-control`。
- 内容卡片使用 `--radius-card`；表单卡片可以使用 `18px` 的现有页面规格。
- 导航、主按钮、状态胶囊使用 `999px`。
- 弹窗的 `28px` 圆角和移动端底部 sheet 的 `26px` 是认证弹窗的特例，不要扩散到普通卡片。
- 新增圆角前先复用上述层级；不要出现 `13px`、`15px`、`22px` 等无语义的单次值。

## 5. 页面结构

标准页面结构：

```text
page-shell
├── PageIntro
│   ├── eyebrow
│   ├── h1
│   └── page-intro__description
└── 一个主要 surface / 一个主要任务
```

规则：

- `PageIntro` 负责说明页面是什么；内容 surface 负责让用户完成任务，不要让两处重复同一段说明。
- 页面顶部留白优先于装饰。没有真实内容关系时，不添加编号、分隔线或图形标记。
- 卡片内部使用清晰的标题、说明、控件顺序；不要把多个不同任务塞进一个表面。
- 空状态应给出下一步行动；错误状态应靠近出错控件；成功状态应说明结果和可继续的动作。

### 短反馈与复制行为

- 复制、保存、撤销等完成后的短反馈统一使用共享 `TransientFeedback` 组件，显示在视口顶部居中的临时反馈层，不在页面底部或卡片内部另起一套 toast。
- 反馈使用 `role="status"` + `aria-live="polite"` 表达成功，使用 `role="alert"` + `aria-live="assertive"` 表达失败；默认显示约 `2800ms`，新反馈会替换旧反馈并重新计时。
- 文案直接描述结果，例如“接入提示词已复制。”、“API Key 已撤销。”、“复制失败，请重试。”；不要使用只对开发者有意义的状态码或内部术语。
- 复制动作必须在成功写入剪贴板后再触发成功反馈；写入失败只显示失败反馈，不得伪报成功。
- 表单字段校验、阻塞性错误和一次性密钥的生命周期提示仍可贴近对应控件展示；它们不是全局短反馈的替代实现。一次性密钥的“已复制/复制失败”仍使用全局短反馈。
- 不得新增 `connection-toast`、页面专属 toast 或自定义 `z-index`；短反馈层使用语义层级 `--z-toast`。

## 6. 组件规则

### 按钮

- `.button` 是统一按钮基类，主按钮使用 `.button--primary`，次按钮使用 `.button--secondary`。
- 按钮最小高度统一为 `44px`；图标关闭按钮也必须提供不小于 `44px` 的点击区域。
- 主要操作使用蓝色胶囊按钮；同一 surface 不应出现两个同等权重的主按钮。
- 次要操作用描边按钮或文本链接，不与主按钮争夺颜色。
- 禁用态保留布局，只降低不透明度并禁止交互。
- 悬停可以轻微上移 `1px`；不要加入弹跳、发光或持续动画。

### 表单

- label 必须真实描述字段，不用 placeholder 代替 label。
- 输入框使用白色/`--surface` 表面、`--line-strong` 边框和 `--radius-control`。
- 聚焦时保留黑色边框，并使用蓝色外圈；焦点必须可见。
- 辅助说明放在字段之后；错误文字使用 `--danger`，不要只依靠颜色，必须有文字说明。
- 验证码、密码和邮箱流程共用 `EmailLoginForm` 的结构和间距。

### 卡片与状态

- 卡片默认 `--surface + 1px --line`，阴影只用于轻微层次，不制造悬浮感。
- 卡片默认内边距 `20px`；内容组内部间距 `8px`，说明文字与行动按钮之间至少 `16px`。
- 行动按钮必须作为独立的行动组排列，不能直接跟在说明文字的 inline 流中。
- 相关字段应合并在一个主容器内，用分隔线或内部间距区分；不要为展示名、ID、状态等小任务各自创建独立卡片。
- 只有一个选项的导航不使用 Tab；直接展示内容标题，避免“导航标题 + 内容标题”重复。
- `receipt` 表达一次处理结果；`authorization-card` 表达授权或高风险确认；`login-panel` 表达登录/注册表单。
- 状态背景只能使用对应的 `*-soft` Token，状态标题和图标使用对应的强色 Token。
- 卡片左侧彩色装饰条、背景渐变或玻璃效果都不是默认组件能力，只有内容语义明确时才允许使用。
- 设置页的状态卡采用“左侧状态说明、右上状态标签、右下行动按钮”的结构；订阅按钮只在有真实订阅记录时显示“管理订阅”，否则显示“订阅”。
- 会员方案这类跨页面行动使用真实链接并在新标签页打开；不要在账号设置页复制支付流程或伪造管理入口。
- 邀请、积分、日报等设置能力使用“分区标题 + 嵌入式卡片”呈现；只有需要切换独立任务时才进入侧栏导航。
- 邀请权益必须显示“已使用 / 总名额”计数；额度由服务端配置，不在标题或说明文案中写死具体人数。
- 用户可见标签使用“新用户邀请”；所有 active 注册账号都可以创建，包括 Filter。Filter 年卡签发是独立能力，不应成为新用户邀请的资格门槛。
- 年卡“兑换”和“签发”是两个不同任务：非 Filter 只展示兑换卡，Filter 只展示签发卡；根据账号权限互斥展示，不把两张卡同时放在页面上。

### 导航

- 桌面端导航保持轻量、低对比；当前项用中性灰背景或明确的当前状态。设置侧栏宽度为 `152px`，侧栏到内容区保持 `24–32px`。
- 设置侧栏和顶部“收藏链接”入口统一使用 `44px` 高的触控区域，避免同一导航层级出现不同尺寸。
- 移动端使用底部浮动导航，不能遮挡主要内容，并保留安全区空间。
- 玻璃效果只用于导航，不用于页面主体、表单或内容卡片。

### 内容显示切换器

- `ViewSwitcher` 是卡片/列表两种内容显示方式的共享组件；发现页和收藏页必须复用它，不要在页面中重新实现。
- 控件使用图标加文字，当前项通过 `aria-current`（链接）或 `aria-pressed`（按钮）表达；移动端仅隐藏文字，不缩小触控区域。
- 切换器轨道固定为 `44px` 高，选项使用中性灰轨道与白色当前项，不额外引入页面专属颜色。

### 弹窗可访问性

- 弹窗必须有可关联的标题，打开后将焦点放入弹窗，Tab 只在弹窗内循环，关闭后把焦点还给触发入口。
- Escape、遮罩和显式关闭按钮都可以关闭弹窗；关闭按钮不能只依靠右上角位置表达含义。

## 7. 认证弹窗规则

认证弹窗必须看起来像站内表单，而不是另一套产品：

- 遮罩使用中性黑色半透明层和轻微模糊。
- sheet 使用 `var(--surface)`，不使用暖色纸张背景。
- 标题、表单和说明沿用站内字体与颜色；珊瑚色只保留给账号入口标签，蓝色只保留给主要行动和焦点。
- 桌面端居中；移动端贴底，顶部圆角，底部保留安全区。
- 关闭、返回和更换邮箱都必须是可键盘操作的真实按钮或链接。

## 8. 动效与无障碍

- 默认动效短、低调，只服务于反馈；优先 `140ms ease` 的颜色、边框或轻微位移。
- 必须支持 `prefers-reduced-motion: reduce`，减少或关闭非必要动效。
- 所有交互控件保留 `:focus-visible`；不要用 `outline: none` 隐藏焦点而不提供替代样式。
- 触控目标至少约 `44px` 高；按钮和导航不能只依赖图标表达含义。
- 文本、边框和状态不能只靠颜色区分；错误、成功、权限和隐私边界要有文字。

## 9. 禁止事项与评审清单

提交新的页面或组件前检查：

- 是否复用了现有 Token，而不是新增一个近似颜色？
- 是否仍然是黑白中性底，蓝色/珊瑚色各自承担清晰语义？
- 是否使用了正确的页面容器和现有组件，而不是复制一套表单/卡片 CSS？
- 是否只有一个主要行动？
- 是否有可见焦点、移动端布局和 reduced-motion 行为？
- 是否避免了无语义的渐变、阴影、圆角和动画？
- 是否把系统内部术语改成用户能理解的动作？

如果新需求确实需要突破规则，先写明“为什么现有语义不够”，再新增 Token 或组件变体；不要用局部覆盖悄悄改变全站规则。
