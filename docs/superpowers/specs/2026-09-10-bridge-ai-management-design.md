# Bridge AI 管理对话设计

日期：2026-09-10。基线：main84ea7ed，已发布并运行的 CLI/Bridge0.3.17。
状态：用户已同意“AI 理解请求、尝试操作、自然回复，固定命令只兜底”的方向；本文等待书面审阅。此文不代表代码或线上行为已变更。

## 1. 问题和选择

实际复现：「升级状态」命中本地控制器；「升级」「升级brige」「重启session」落入业务 AI，得到没有执行依据的“请到管理端操作”。真实 Runtime/MCP 健康，业务 session 已是0.3.17。问题是管理能力缺失，不是版本未生效。

比较三种方案：

- 仅扩充固定别名：改动小，但用户仍需猜系统认识哪些表达；作为离线兜底保留，不作为主方案。
- 给业务 AI 开放通用命令执行：可操作范围过大，文章和历史中的指令可能触发本机操作；不采用。
- 独立 AI 管理解释与受限执行器：采用。AI 理解和组织语言，Bridge 决定权限、执行操作、记录真实结果。复用现有更新和 MCP 恢复机制。

本次只解决本地 Bridge 的更新、连接恢复、会话重建及相关回复。不扩大为 Hosted Agent、Web 管理端、正文抓取修复或全局 CLI 自动覆盖；不修改模型选择、账户权限、邮箱配置或服务器隔离。

## 2. 自然语言和执行分离

收到绑定 owner 的消息后，原生固定控制命令优先保障故障可用性；其他合格的直接文本通过独立管理解释轮判断 `management / business / clarify`。不以“包含升级二字”作为执行授权。

管理解释轮只接收当前直接消息、允许能力目录和最小管理对话上下文，不接收业务历史、正文、引用、分享卡片、转发附件或其他 MCP 的内容。对“这段话写着升级，帮我解释”“不要升级”“我昨天升级过”等不得执行。意图不明确时追问，不猜操作对象。

宿主适配器为该轮提供无工具、无 Web、无业务 MCP 的隔离配置；只输出经过 schema 校验的管理请求。Bridge 将请求交给本地管理能力接口执行，再将结构化结果返回 AI。这个内部接口是受限管理工具的执行边界，不从普通 assistant 文本、Markdown/JSON 片段或业务工具结果提取可执行指令。

Codex 与 Claude Code 都需验证隔离配置与结构化结果路径；宿主不能可靠满足约束时，明确标为不支持 AI 管理并保留原生命令，不放宽隔离。不得假定当前不支持 dynamicTools 的业务接口已经有本地管理工具。

## 3. 受限管理能力

能力集合固定，不接受命令字符串、任意路径、PID、远端地址、下载安装 URL 或任意目标版本：

- `get_status`：返回实际运行版、最新已验证版本、检查时间、更新操作阶段、Runtime/MCP 状态；区分未知与最新。
- `check_update`：只检查固定可信更新源，复用现有校验、节流、候选状态机，但不因本次请求排队安装。原生「检查更新」也采用此语义；定时自动更新继续按既有策略运行，不能把一次查询当成关闭自动更新或取消既有任务。
- `request_update`：表达升级意图，先查再尝试；没有新版时准确告知，有权限变化时生成候选绑定的批准请求。AI 没有确认权限变化的工具。
- `defer_update / cancel_update`：只作用于当前候选，复用现有安全切换点与取消语义。
- `retry_connection`：调用现有 MCP/Runtime 恢复机制，遵守退避；不能绕过 OAuth，也不能替用户授权。
- `restart_session`：只重建本 Bridge 的业务会话，保留微信登录、owner、消息队列、去重记录、历史和摘要任务。不等于 `/reset`，不清空历史，不操作整个 Codex App 或其他任务。

“升级”默认指当前 Bridge；“升级全局 CLI”在本次能力外，应准确解释范围，而非谎称已升级。单独“重启”若不明确指会话还是服务，先澄清。清空历史继续要求原生 `/reset`，AI 管理不新增删除入口。

## 4. 权限、状态和生命周期

权限检查使用真实入站身份和消息关联，模型不能传入或伪造 owner、授权状态、确认码、操作 ID。模型选择参数还须通过白名单和当前状态校验。未知/重复/并发请求 fail closed；每条消息关联一个幂等请求，操作结果独立持久化。AI 意图只请求既有受限能力，不代表新的权限批准。

重建会话在当前业务 turn 安全结束后处理。当前管理回复送达后才能关闭相应业务适配器/废弃旧 session 引用；不取消已承诺的出站消息。下一业务 turn 创建版本匹配的 session 并重放保留历史，只有实际创建/持久化新 session 身份后才能标记完成。之前只能说“已安排，下条消息会使用新会话”，不能提前宣称重启完成。会话引用失效不抹除历史；重建失败保留可重试操作与队列。

管理解释/措辞不占用业务 session，不依赖 Attention OAuth，不与业务状态并发写入。沿用 service loop 单写入者模型：异步模型轮只返回结果，由 tick 验证并提交操作。阻塞队列不能永久挡住管理命令；保留控制扫描上限、owner 校验和普通业务顺序。

更新审批仍绑定候选完整身份、版本、权限摘要及到期时间。说明和确认命令由 Bridge 生成；模型不能把“好”“升级吧”转成新增权限批准。回滚、取消、重复确认、过期确认、网络故障和启动后对账复用0.3.17机制，不创造第二套更新状态。

## 5. 自然回复和可靠兜底

默认让 AI 基于结构化执行结果生成简短中文回复，回答用户刚问的问题，不每次列命令清单。状态字段区分 `not_started / queued / running / awaiting_confirmation / succeeded / failed`，同时给出下一步。

事实区包含实际版本、操作阶段、失败原因、是否可重试及真实重试安排，不包含 token、邮箱、文件内容或任意外部提示词。没有排队不说“正在升级”；只有检查通过才说“已是当前可用版本”；没有持久化重试计划不承诺自动重试。升级成功、MCP恢复、正文读取和摘要补全是四件事，不能互相替代。

请求已通过解释与校验后，执行不等待 AI 组织回复。解释轮或回复轮各有总计8秒超时预算；解释超时不得猜测执行，只提示未执行及可用的原生命令，回复超时则直接展示已有操作的事实结果。宿主离线仍可执行原生命令，避免升级/重连也被 AI 故障堵住。取消操作优先于措辞任务。后台事件的措辞采用独立无工具轮，不重新触发管理意图或操作。

权限差异、候选版本、确认命令、有效期属于不可改写的安全字段，由 Bridge 拼接到自然语言旁；AI 不能省略或改造。关键版本/执行状态采用 Bridge 拥有的明确字段展示，AI 只能引用已有结果字段；结构化引用无效或状态不一致时使用事实兜底。自由文本负责简短解释，不作为权威进度；不声称 schema 或第二个模型能够消除所有语言幻觉，需用回归用例检查无依据完成声明，并在发现不一致时丢弃该回复。

原生命令「状态」「升级状态」「检查更新」「重试」以及窄别名「升级」「升级 Bridge」「升级bridge」「升级brige」继续无需模型即可进入对应控制流程。自然语言理解不是不断加正则；别名只提高离线可用性。

## 6. 验收、版本与交付

先测后改，测试覆盖：

1. 实际用户表达和错拼、口语表达；普通提问、否定、引用、代码、文章指令、非 owner 不执行；歧义先澄清。
2. 管理工具真实执行并把结果提供给 AI；没有工具能力时不得返回不存在的“本机管理端”。AI回复失败不阻断原生控制。
3. MCP OAuth失效时管理仍可用；宿主不可用时原生命令可用；每种状态的语言不夸大结果。
4. 版本无更新、更新失败、取消、退避、审批到期、候选变化、重启与回滚；“只检查”不安装。
5. 会话重建保留全部数据，下一业务消息产生新的 session 身份；不得冒充 `/reset` 或重启整个宿主。
6. 同消息重复投递、控制请求遇到阻塞队列、出站未送达、进程退出恢复；实际结果通知不重复执行操作。
7. Codex/Claude适配器隔离断言、陌生工具/输出拒绝；机密不进入管理日志或模型输入。

沿用现有 CLI、controller、launcher 与 channel 测试，补管理解释/执行/回复模块的针对性测试，运行类型、产物一致性、受控 lifecycle 与构建检查。真实微信验收至少包括：升级状态、升级（当前无新版）、连接恢复、保留历史重建后的一条业务消息。不把 mock 测试称为真机闭环。

不得覆盖已发布0.3.17文件；新版本和权限指纹按实际实现重新核验。如果向模型暴露管理能力改变安全契约，必须如实更新权限描述/指纹与兼容性测试，不伪装成已有授权。旧0.3.17若不能完整解释变更，就保留明确的电脑端一次性引导要求，不为达到自动更新效果绕过批准。

当前只准备设计与后续实现。合并、部署、设备服务替换及新增权限批准须遵循各自授权，不能把方向认可当作一揽子发布或权限许可。
