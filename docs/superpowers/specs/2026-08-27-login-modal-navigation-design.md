# Attention 站内登录入口统一模态设计

**状态：** 已确认
**日期：** 2026-08-27

## 目标

Attention 站内所有主动登录入口统一使用现有 Next.js 拦截路由，以模态窗覆盖当前页面；用户直接打开或刷新 `/login` 时仍保留可独立工作的登录页。

## 范围

- 将收藏弹窗、收藏页、公开流会员入口、会员页、站点导航和登录表单内的登录跳转统一为 Next.js 客户端软导航。
- 密码修改触发的 `reauth=1` 也使用登录模态，并继续锁定当前账号邮箱、仅允许验证码验证。
- 统一构造 `/login`、`return_to` 和可选 `reauth` 参数，避免各入口重复编码。
- 登录完成后继续使用服务端返回的安全 `redirect_to` 完成页面刷新，使新会话立即被服务端组件识别。

## 非目标

- 不删除独立 `/login` 页面。
- 不把直接访问、浏览器刷新、书签或外部链接伪装成拥有背景页面的模态导航。
- 不改变 OAuth `/auth` 协议登录、服务端鉴权重定向或受保护页面的直接访问回退。
- 不改变验证码、密码、会话、注册或 `safeReturnTo` 协议。

## 设计

### 统一登录链接

新增小型 `LoginLink` 组件和纯函数登录地址构造器。组件内部使用 `next/link`，接收目标 `returnTo`、可选 `reauth`、样式和子元素；构造器负责稳定编码查询参数。普通服务端组件和客户端组件都复用这一入口。

现有已使用 `Link` 的入口可直接迁移到该组件；普通 `<a>` 和 `window.location.assign('/login…')` 必须替换，避免浏览器硬导航绕过拦截路由。

### 拦截路由与重认证

`app/@auth/(.)login/page.tsx` 同时解析 `return_to` 与 `reauth`。普通登录保持当前行为；当已登录用户通过站内软导航进入 `reauth=1` 时，不执行“已登录即返回”的重定向，而是在模态中使用当前账号邮箱渲染 `LoginModule`，并启用 `forceCodeOnly`。

直接打开相同 URL 仍落到 `app/login/page.tsx`，继续使用现有独立页面重认证回退。

### 导航与关闭

站内点击登录链接后，Next.js 平行路由保留当前页面并在 `@auth` 槽位渲染 `AuthModal`。关闭按钮继续调用 `router.back()` 返回原页面。验证成功后保留现有硬刷新到安全返回地址的行为，不依赖模态历史状态。

## 错误与安全

- `return_to` 在独立页和拦截页继续通过 `safeReturnTo` 过滤。
- 重认证邮箱只取服务器会话中的 `primaryEmail`，不接受调用方提供邮箱。
- 若没有有效会话，`reauth=1` 退化为普通登录模态，不泄露账号信息。
- 外部链接、刷新和服务端重定向仍有独立登录页兜底。

## 测试与验收

1. 登录地址构造器正确编码普通返回地址和 `reauth=1`。
2. 收藏、会员、导航、忘记密码与密码修改入口不再使用会导致硬导航的登录 `<a>` 或 `window.location.assign('/login…')`。
3. 已登录用户软导航到 `reauth=1` 时看到锁定邮箱的验证码模态，而不是被立即重定向。
4. 普通已登录用户打开登录模态时仍返回目标页面。
5. 直接访问或刷新 `/login` 仍渲染独立页面。
6. 相关单元测试、类型检查、主工作树 lint 和 Web 构建通过。
