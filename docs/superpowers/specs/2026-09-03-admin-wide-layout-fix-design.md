# 管理端宽屏布局修复设计

## 问题

`/admin/users` 在宽屏下没有充分利用可用横向空间。现有外层采用居中的固定最大宽度，并为侧栏保留较宽列和间距；此外，管理页虽然不渲染主站侧栏，根布局的 `<main>` 仍继承主站侧栏预留的 `216px` 左边距。这两层约束共同造成显著的左侧空白，同时主表格仍需要横向滚动或在截图中显得被右侧裁切。此前验收只覆盖 1280px 和 390px，且仅检查页面是否横向溢出，没有检查宽屏空间利用率与左右视觉平衡。

## 方案选择

考虑三种方案：

1. 只提高固定最大宽度：改动最小，但在更宽显示器上仍会重新出现大块留白。
2. 页面完全贴边：空间利用率最高，但管理界面会显得拥挤，标题、卡片和浏览器边缘缺少安全距离。
3. 自适应安全边距：让管理页宽度跟随视口增长，仅保留响应式页边距；同时收紧侧栏列宽和栏间距，让主内容占用剩余空间。

采用方案 3。它能直接修复宽屏留白，又保留可读的页面边界，并且不改变管理端的数据流或交互行为。

## 布局

- 桌面端外层使用全可用宽度，左右安全边距随视口在 16–40px 之间变化，不再由 `1440px` 居中上限制造额外留白。
- 当页面包含 `.admin-users-shell` 时，根布局 `<main>` 不再预留主站侧栏边距。
- 侧栏保持独立身份与导航结构，但列宽缩小为适合现有内容的范围；主内容列使用全部剩余宽度。
- 表格继续设置自身最小宽度，并只在 `.admin-users-table-wrap` 内横向滚动，页面本身不得出现横向滚动。
- `780px` 以下继续使用现有的顶部身份摘要、横向导航和单列筛选布局。

## 验收

- 在 1280、1440、1800px 桌面视口检查：左右外边距均衡且不超过设计安全边距；主内容明显扩展；页面无横向滚动；表格不被页面边缘裁切。
- 在 390px 手机视口检查：身份、导航、筛选和表格内部滚动保持可用。
- 运行管理页组件测试、类型检查、Lint 和生产构建。
- 部署后在真实暂存环境重复桌面宽屏和手机视口检查，并确认控制台无新增错误。

## 范围

只调整管理端布局 CSS 和必要的布局回归测试；不修改权限 API、认证、权益操作和审计数据逻辑。
