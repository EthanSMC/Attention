# Attention CLI、MCP 与 Agent 的能力边界

日期：2026-09-10。状态：用户已认可产品定位和职责划分，本文待书面审阅。
本文定义演进目标和分期，不代表功能已经交付；不授权合并、推送、部署或改动设备权限。

## 1. 已确认的产品决定

Attention CLI 是一等、完整的日常产品操作入口，不只是安装器或 MCP 的故障备用工具。主要业务操作最终应能在不打开 Web 产品、不连接 MCP 的情况下完成。首次登录或其他明确的安全确认仍可使用浏览器，不能把“日常无需网页”承诺成无交互授权。

CLI 不充当 Agent：不维护 AI 聊天、不自行规划步骤、不选择模型或动态调用工具。它是确定性的能力客户端。Agent 可以调用 CLI，但 CLI 不因此成为 Agent。

CLI 与 MCP 是并行入口，不按“CLI 只能本地、MCP 只能云端”硬划功能。一个业务动作可以同时有 Web、CLI、MCP 三种入口，业务规则只实现一次。

## 2. 职责与执行位置

| 部分 | 拥有的职责 | 不承担的职责 |
|---|---|---|
| Attention Core / 服务端能力模块 | 业务规则、身份权益、数据、去重、可见性、审计与服务端任务状态 | 根据聊天自由规划本机命令 |
| Attention 本机能力模块 | 安装配置、诊断和本机版本生命周期的确定性操作 | 收藏规则、摘要推理、自由对话 |
| CLI | 参数解析、调用 API 或本机模块、输出结果、显式等待 | 复制 Core 规则、隐式启动 Agent |
| MCP adapter | 能力发现、参数和结果的协议适配、调用共享业务能力 | 再实现一套收藏/权益/重试策略 |
| Web | 人可理解的交互及对应安全确认 | 独占本来适合程序调用的日常业务能力 |
| Codex / 其他用户 Agent / 后续 Hosted Agent | 理解意图、规划步骤、选择能力、推理与组织回复 | 绕过 Attention 的鉴权和安全限制 |
| 微信 Bridge | 收发、去重、必要的会话对接和自身运行/升级安全切换 | 新增 AI 意图分类器、话术模型或业务编排系统 |

复用的单位是服务、契约与本机模块，不是要求所有入口都执行同一个命令。CLI 业务调用直接走受支持的 Attention HTTP API，不先启动 MCP Client；MCP 在服务端调用共享服务，不通过 Shell 启动 CLI。CLI 不打包服务端数据库访问代码、数据库凭据或 `server-only` 实现。

## 3. 能力覆盖目标

完整是指主要日常产品操作，不代表首批实现全部命令，也不自动包含支付、管理员权限调整或凭据导出。

| 能力域 | CLI 目标 | 执行方与边界 |
|---|---|---|
| 账号与授权 | 登录、查看当前身份/授权状态、退出自己的 CLI 授权 | 使用明确的 CLI 客户端身份；不读取宿主私有凭据冒充登录 |
| 收藏 | 新增、候选选择、列表、详情/状态、调整公开或私密 | 服务端做所有权、实时权益、可见性和去重判断 |
| 公开发现与检索 | 查询公开流、搜索内容 | 与其他入口共用会员、范围和速率限制 |
| 内容处理 | 查询结果、请求受支持的处理任务、提交已生成的合法补全结果 | 推理由既有处理服务或已配置执行端负责；CLI 不生成假摘要 |
| 日报与订阅设置 | 查看和修改可程序化的日报设置、查询权益/订阅状态 | 不隐式授权支付、续费或其他安全确认 |
| 本机管理 | 配置、诊断、查看全局 CLI/Bridge 实际版本、请求升级与查询进度 | 操作本机模块，不通过云端业务 MCP 远控设备 |

后续新增适合程序执行的业务动作，能力清单应记录 CLI/API/MCP/Web 的覆盖状态、权限与明确例外，不要求四个入口同时上线，也不把“未实现”伪装成永久安全例外。

## 4. API、鉴权与一致性

当前一些 Web API 使用浏览器 Session；不能让 CLI 导入 Cookie、伪装浏览器 Origin 或跳过 CSRF 检查。需要新增或复用正式支持客户端授权的 HTTP adapter，复用现有主体解析、resource audience、scope、实时权益、限流与审计路径。不能直接把 Web 路由改成同时接受任意 Bearer token。

CLI 的授权机制优先沿用项目 Authorization Code + PKCE，兼容项目允许的受限 API Key 方式；不把 MCP 宿主的 token 缓存位置当成稳定公共接口。CLI 与 MCP 可以代表同一账号，但凭据生命周期、客户端身份、scope 与 audience 不可混用或绕过。

客户端 credential 由安全存储模块管理。token 不出现在命令参数、stdout、日志或普通错误对象中；非交互式凭据输入通过明确的安全输入方式处理。具体登录实现须有单独的鉴权测试和兼容性审查。

同一账号经不同入口调用同一能力，必须得到一致的业务判断与稳定错误。注册表/契约维护唯一的参数、结果及错误定义；CLI 只负责传输与显示，不自己推断权益或重建规则。

写操作使用明确的幂等约定；已有非幂等操作不能被客户端盲目重试。请求成功但响应丢失时先查证或用同一幂等键重试，不因为 MCP 报错就换 CLI 再创建一次。鉴权失效和权限不足不是可通过换入口解决的错误。

## 5. CLI 的交互与长任务

所有日常命令有稳定 `--help`；人类可读输出与 `--json` 是同一结果的两种呈现。JSON 模式 stdout 只输出约定结构，升级提醒、进度与诊断放 stderr。失败包含稳定 code、request_id 及适用的下一步，不只返回一段自然语言。

列表采用服务端分页，不默认拉取所有数据。修改和取消只作用于明确对象。交互确认不能替代服务端授权；非交互模式不得隐式回答“是”。

长任务只有在执行端已接受并持久化后才返回任务 ID/已排队状态。CLI 可显式等待并轮询真实状态，但不在退出后自行留下隐藏 Agent 或伪造定时重试。取消、重试必须由执行端提供对应能力，不能只在 CLI 打印成功。

收藏已保存、正文已读到、摘要已生成、补全已写入是不同事实。当前已有摘要提交和收藏状态能力，不等同于已经具备通用“启动/取消摘要后台任务”接口。未配置处理服务、执行端不可用或任务能力未交付时返回明确的不可用结果，不偷偷用本地 Codex 来补齐。

## 6. 与 Shell 和 Bridge 的关系

用户已认可开放微信 Codex 的受限 Shell，保留限定目录的写权限和无 sudo 边界。CLI 是工具，开放 Shell 不代表授权任意读取、改动、访问网络或通过文章指令执行本机操作。

本机升级、诊断可不依赖 Attention 云端 MCP OAuth；业务 CLI 则需要有效业务授权和 API 网络连接。因此上一版方案里的“本机阶段保持 Shell 外网关闭”不能套用成完整业务 CLI 永远无网络。业务阶段必须同时完成执行级网络权限设计与真实宿主验收，不能靠提示词假装限域。

Bridge 的升级仍须等待安全切换点，保留微信登录、队列和历史。Attention CLI 对运行进程发受限控制请求，不并发覆写 Bridge 的状态文件。审批、安装产物和凭据不得因 Shell 开放而变成模型可直接改写的批准依据。

本机管理的详细约束参考 `2026-09-10-attention-cli-shell-management-design.md`；若与本文冲突，以本文的产品边界为准。前一版 `bridge-ai-management` 中的额外模型和话术模块不再采用。已有摘要工作流的迁移另行分期，不借此次改动一次重写整个 Bridge。

## 7. 分期交付与验收

本目标涉及 CLI 协议、云端 API/鉴权、本机运行时三个子项目，按垂直闭环交付，不在一个改动中全量铺开。

1. **C1 本机闭环与 CLI 输出基础**：先完成诊断、运行版本/候选状态、Bridge 检查/升级/取消的 CLI 接口及结构化结果；移除未交付的 Bridge AI 管理实现，开放经过真机测试的 Codex Shell。全局 CLI 升级继续与 Bridge 升级区分。单独验收 OAuth 故障时的本机管理与安全切换。
2. **C2 独立业务客户端闭环**：CLI 自身授权、正式 HTTP adapter、共享调用契约；先打通身份查询、收藏列表、新增/选择候选与状态查询。无需 MCP 或 Web Session，验证跨入口同主体/权限/幂等一致性，并补齐业务出网策略。
3. **C3 日常能力覆盖**：收藏可见性、公开发现、检索、日报设置及其他已支持的日常操作，逐项维护能力矩阵，避免命令和服务端漂移。
4. **C4 处理任务控制**：在执行端具备真实任务协议后提供提交、等待、状态、取消与重试；执行端不可用的测试与成功路径同等重要。不是趁机在 CLI 内实现 Agent。

每一期分别制定实施计划和验收，不把后续任务描述成已可用。版本、安装产物、权限指纹、兼容性与回滚必须在实际发布前验证；旧用户不能静默接受新增设备权限。
