# 微信 Codex 专用本机浏览器

## 已确认的产品选择

用户要求直接向微信 Codex 提供浏览器能力，拒绝逐篇手动导入正文，
并选择专用、保留会话的本机浏览器，而非接管日常浏览器。
首次显式启用后，收藏或重试请求即授权读取该请求关联的目标文章，
不重复要求导入确认；不授权操作无关网站或浏览其他个人页面。

Bridge 只负责微信传输及自身运行与升级管理。浏览器是 Attention 提供给
Codex 的本地能力，正文处理、收藏权限、标题摘要写回仍由 Attention 负责。
本设计不代表代码已经实现、浏览器已经启用或线上已经部署。

## 现状与失败证据

- 0.3.20 的 MCP 账号及收藏状态查询已成功，不能将正文失败归因于 OAuth。
- 目标微信文章在服务器读取环境返回 `verification_required`；手机完成
  验证不能证明服务器请求已获许可。
- `codex-home.ts` 刻意不继承桌面 Codex 的插件和无关 MCP；
  `restricted-profile.json` 只允许 Attention MCP，并禁止 browser automation。
- 当前消息循环等待整个 Agent turn 后才继续接收消息，中途进展不会即时转发。
  增加浏览器前必须避免把人工验证等待变成另一个长时间阻塞。
- 现有内容补全服务会更新共享 content；不能直接把登录会话可见的私人正文
  写入这一共享对象。

## 方案比较与选择

采用独立持久化浏览器：可复用在该浏览器内完成的验证，同时隔离日常标签页。
接管日常浏览器可复用更多已有登录态，但权限面更大，用户未选择。
逐篇复制或确认导入操作更简单但体验不符合用户要求，不作为主要路径。

## 架构与接入

新增 Attention 本地浏览器 MCP 服务，由安装/配置层为微信 Codex 注册。
浏览器适配器使用锁定版本的 Playwright 实现浏览器操作，不把原始 unrestricted
Playwright 工具集或任意代码执行入口直接暴露给模型。

服务使用独立目录 `~/.attention/browser/profile`，不复制、导出或读取日常浏览器
profile；目录仅当前系统用户可访问。浏览器按需启动、空闲关闭进程，profile
保留。一个实例只允许一个 profile 持有者；无桌面环境时返回 unavailable，
不能宣称已打开验证窗口。首版验收平台为用户当前 macOS；其他平台不假报支持。

本地 MCP 通过受管理的 stdio 连接，不开放公网调试端口。网页不能访问本地
管理接口。配置显式列出允许的两个服务：Attention 与本地浏览器；不继承其他 MCP。
更新 readiness 检查、权限清单、说明与会话指纹，浏览器故障仅降级浏览器能力，
不能让普通聊天或现有 Attention MCP 启动失败。

## 模型可使用的能力与边界

提供打开文章任务、查看页面/正文、受限滚动及展开正文、查询任务状态、
显示验证窗口、关闭任务等能力。页面操作限定于当前文章任务的标签页；
不提供任意 JavaScript、文件上传下载、Cookie 导出、支付、发布、账户设置等操作。

打开请求以 collection ID 和当前账号为输入，服务从 Attention 获取当前所属
收藏的真实来源 URL，并获取短期、绑定账号/收藏/来源版本的授权，而非信任模型
随意提供的 URL。限制目标、跳转和子资源；保留公共地址校验，拒绝内网、localhost、
文件协议、URL 凭据和下载。不能仅靠提示词或浏览器包的域名选项充当安全边界。
验证页面仅在已批准的来源流程中供用户操作，不能自动破解、代答或规避验证码。

正文与页面提示都是不可信数据，不能授权访问新目标、调用管理工具或上传其他数据。
浏览器 profile 凭据永远留在本机；提取的文章正文会进入 Codex 模型上下文及
Attention 的补全流程，这项数据流须在首次启用说明中明确。

## 读取、验证及重试

1. Attention 优先使用现有来源读取；验证或确实需要本机渲染时，Agent 可调用
   专用浏览器，不要求用户逐篇导入。
2. 本地浏览器提取实际渲染的标题和正文，返回最终 URL、提取时间、内容哈希、
   来源版本、正文完整性及读取状态。验证码、登录提示和空壳页面不能作为正文。
3. 若仍需验证，返回 `needs_user_verification` 和任务引用，保留目标标签页，
   必要时显示专用窗口。Agent 当轮结束并说明需要在本机该窗口完成验证；
   不叫用户去手机验证，也不保持模型调用等待用户操作。
4. 用户说“验证好了，重试”时，针对该任务进行一次新的实际检查；仅查询旧状态
   不得声称已经重试。没有新验证结果时不自动反复刷新验证页。
5. 读到可靠正文后，由 Agent/Attention 生成并保存标题摘要，再读回核验。
   未能保存、部分正文和验证失败分别报告，不冒充成功。

一次读取动作上限 60 秒；网络临时失败仅允许一次有间隔的自动重试。
人工验证等待释放执行资源，任务引用保留 30 分钟，过期后可通过新的明确请求
重新创建；profile 不随任务过期删除。撤销授权或切换账号立即使旧任务失效。

## 数据一致性与权限

本地证据必须经 Attention 账号权限、收藏归属、来源版本、大小和格式校验；
客户端声称“已验证”不等于服务器证实公开来源。正文不进入普通运行日志。
每次提取上限 2 MiB，正文截断必须标记，不能以截断正文冒充完整文章。

本机持久会话所得补全结果使用账号/收藏级覆盖记录，记录来源与证据哈希，
不直接改写其他用户共享的 content。私人正文不进入公开 feed 或公开读页；
用户自己的收藏状态接口及私人视图按已有人工编辑优先级显示该覆盖值。
首版不新增“把本地证据发布为公共内容”的隐含路径。
写入绑定来源版本并使用幂等键；陈旧任务、跨账号任务和并发人工修改不得覆盖。
升级后的 MCP/客户端需明确区分私人补全已就绪与公开内容仍未补全。

## 对话与任务运行

浏览器等待不阻塞微信收消息。传输层继续持久化新消息，Agent 执行按账号串行，
不得为了提高响应速度并发修改同一个 Codex 会话。转发经筛选的 Agent 进展，
不转发思维链、工具原始结果、凭据或正文全文。新消息可以入队，但不谎称其业务
操作已执行；任务有整体截止时间和取消路径，不能无限等待浏览器或模型。
业务意图及正常回复仍由 Agent 理解组织，不在 Bridge 增加文章重试关键词状态机。

## 权限升级与交付

本次用户选择是设计授权；落地时通过正式启用路径保存版本化浏览器授权及权限指纹，
不能手改指纹假装已经确认，也不能让其他旧安装静默继承浏览器权限。
浏览器依赖、安装体积及失败回退单独说明；不在 CLI 每次启动临时安装 latest。
原微信登录和消息队列保持不变，不默认升级全局 CLI、发布 npm 或部署服务器。

## 验收

- 浏览器能力被真实注册并可调用；不可用时聊天和 Attention MCP 仍可用。
- 正常文章从本机实际页面获得正文，生成标题摘要，写入后以所属账号读回一致。
- 使用用户提供的微信链接做端到端测试：从微信请求到浏览器读取、补全、读回及
  微信最终回复；若确需人工验证，明确暂停在该真实步骤，不把模拟用例当成功。
- 验证后同一专用 profile 再读；任务等待中发送“在吗”，确认消息仍能被及时接收，
  并验证取消/超时不会丢失队列或重复写入。
- 验证页、空正文、部分正文、失效任务、跨账号引用、来源变化、重复请求、
  人工修改冲突、私有结果泄露、恶意页面指令、私网跳转及 browser crash 均有测试。
- 测试权限升级及授权撤销，确保不继承日常浏览器资料、不记录凭据、不开放远程调试。
- 运行相关 contracts、CLI、服务端、视图及迁移测试和类型检查；部署须另行确认。
